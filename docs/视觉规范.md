# 视觉规范：子比主题（Zibll）设计语言

界面视觉与交互以 [zibll.com](https://www.zibll.com/1997.html) 为参考基准。本文记录**权威令牌取值**及其来源，避免后续维护时重新猜测或重新抓取。

## 令牌取值从哪来

**不是目测近似，而是抓取实际渲染的计算样式。** 用 playwright-core 加载 zibll.com 的首页 / 文章页 / 商城页，读取：

- 全部非 `--wp-` 前缀的 CSS 变量
- 约 4000 个节点的圆角 / 阴影 / 字体 / 背景 / 文字色**频次分布**
- 9 类组件（header / navLink / card / input / primaryButton / footer / sidebar / heading / body）的完整 `getComputedStyle`

频次分布是关键：出现 200 次的值才是主题的招牌值，出现 3 次的可能只是一次性覆盖。

抓取脚本：`.scratch/probe-zibll.mjs`（已沉淀到 skill `web-visual-parity/scripts/probe-reference.mjs`）。

## 核心令牌

全部定义在 `src/index.css` 的 `:root`。改色请改这里，不要在组件里写死色值。

### 品牌色

| 令牌 | 取值 | 用途 |
| --- | --- | --- |
| `--theme-color` | `#ff3f9f` | 主色，链接悬停、激活态、主按钮 |
| `--theme-color-hover` | `#f6268e` | 悬停加深 |
| `--theme-color-active` | `#e01f7d` | 按下加深 |
| `--theme-color-soft` | `rgba(255,63,159,.1)` | 浅底（eyebrow 标签、引用块） |
| `--theme-gradient` | `linear-gradient(135deg,#ff6bb0,#ff3f9f 55%,#f5208d)` | logo 底、图标底 |

### 文字层级

子比用 `--key` / `--main` / `--muted-1..4` 四级灰阶，这里沿用同样的层级语义。**但三个 `--muted-*` 灰阶未照搬子比原值**——原值达不到 WCAG AA 对比度要求，已按下节所述压暗：

| 令牌 | 本工程取值 | 子比原值 | 用途 |
| --- | --- | --- | --- |
| `--key-color` | `#333333` | `#333` | 标题、强调文字 |
| `--main-color` | `#4e5358` | `#4e5358` | 正文 |
| `--muted-color` | `#636363` | `#777` | 次要说明 |
| `--muted-2-color` | `#696969` | `#999` | 元信息（时间、篇数） |
| `--muted-3-color` | `#6d6d6d` | `#b1b1b1` | 占位、装饰 |
| `--muted-4-color` | `#d2d2d2` | `#d2d2d2` | 分隔、禁用（**仅描边，不承载文字**，故未压暗） |

压暗后三级灰阶的间距被压得很窄（`#636363` / `#696969` / `#6d6d6d`），肉眼几乎难以分辨。这是 AA 约束下的必然结果：正文对比度要求 4.5:1，等价于灰阶不得浅于约 `#6e6e6e`，三级可用的取值区间本身就只剩很窄一段。**若要恢复子比那种层次分明的浅灰，唯一办法是放宽对比度标准**，而不是继续在取值上找平衡。

### 背景与描边

| 令牌 | 取值 | 说明 |
| --- | --- | --- |
| `--body-bg` | `#f5f6f7` | 页面底色 |
| `--main-bg` | `#ffffff` | 卡片 |
| `--muted-bg-2` | `#f6f7f8` | 输入框默认底 |
| `--line` | `rgba(50,50,50,.06)` | 极淡分隔线 |

**子比靠阴影分层，不靠描边**——卡片默认 `border: 0`。这是它观感干净的主要原因。

### 阴影

| 令牌 | 取值 |
| --- | --- |
| `--main-shadow` | `0 0 10px rgba(116,116,116,.08)` |
| `--main-shadow-hover` | `0 0 10px 8px rgba(116,116,116,.08)` |
| `--pop-shadow` | `0 8px 24px rgba(0,0,0,.12)` |

注意 `--main-shadow` **没有偏移量**，是无方向性的柔和光晕，不是定向投影。悬停时扩散而非下移。

### 圆角

| 令牌 | 取值 | 用途 |
| --- | --- | --- |
| `--radius-sm` | `4px` | 控件、按钮、输入框 |
| `--radius-md` | `8px` | 小卡片 |
| `--radius` / `--radius-lg` | `12px` | 卡片 |
| 胶囊 | `999px` | 标签 pill |

### 动效

```css
--transition: color .2s, background .3s, opacity .3s, box-shadow .3s, transform .3s;
--ease: cubic-bezier(.22, 1, .36, 1);
```

子比用**一条统一的多属性过渡**，而不是每个属性各写时长。

### 布局

| 令牌 | 取值 | 说明 |
| --- | --- | --- |
| `--mian-max-width` | `1300px` | 内容宽 |
| `--header-height` | `68px` | 页头高 |
| `--header-offset` | `88px` | 内容顶部避让（移动端 80px） |

> `--mian-max-width` 的拼写（`mian` 而非 `main`）**沿用子比原主题**，便于日后对照其源码时能直接搜到。

### 页头毛玻璃

```css
background: rgba(255, 255, 255, .8);
backdrop-filter: saturate(5) blur(20px);   /* 注意是 5，不是 180% */
```

`saturate(5)` 是实测值。常见的 `saturate(180%)` 是 macOS 磨砂玻璃的取值，**不是**子比的值——两者观感差异明显（前者让页头背后的色彩更浓）。

底色分两态：默认 `.8`，页面滚动后加 `.is-scrolled` 提到 `.94`（并补一道极淡阴影）。
对照截图时注意这一点——`11-页头毛玻璃.png` 是在滚动状态下截的，读到的是 `.94` 而非 `.8`。
（移动端另有 `.97` 覆盖，见 `src/index.css` 的媒体查询。）

页头行为：**下滑隐藏、上滑显示**；顶部 80px 内始终显示；菜单展开时禁止隐藏。

## 与组件库的衔接方式

不逐个改组件，而是**把令牌映射到 shadcn 令牌**，让未改动的组件自动继承：

```css
--primary: var(--theme-color);   --primary-foreground: #ffffff;
--background: var(--body-bg);    --foreground: var(--main-color);
--border: var(--line);           --ring: var(--theme-color);
--destructive: var(--color-red); --accent: var(--theme-color);
```

同时**保留全部旧令牌名**（`--font-serif`、`--radius`、`--font-size-display` 等），把改动面收敛在令牌层。

## 响应式断点

| 断点 | 变化 |
| --- | --- |
| ≤1200px | 文章网格 3 列；浮动工具条内收 |
| ≤1024px | 首屏横幅改两列比例；详情页侧栏收窄 |
| ≤900px | 导航折叠为下拉；网格 2 列；详情页侧栏隐藏 |
| ≤640px | 网格 1 列；页头压缩；快捷入口保持 2 列 |

实测：13 个宽度（320→1920）× 7 个页面共 91 项**零横向溢出**。

## 浏览器兼容性约束

产物 CSS 的实测结论（审计脚本见 skill `web-visual-parity/scripts/audit-compat.mjs`）：

| 项 | 现状 | 约束 |
| --- | --- | --- |
| `oklch()` | 0 处 | 令牌全用 hex/rgba，覆盖了 Tailwind 默认调色板 |
| `color-mix()` | 全部在 `@supports` 内 | Tailwind v4 自带守卫，可放心 |
| `backdrop-filter` | 8/8 带 `-webkit-` 前缀 | 旧 Safari 必需 |
| 范围语法 `(width >= 640px)` | 产物 0 处 | `@utility` 内的会被构建降级；**手写的不会，需自查** |
| `:has()` | 仅 Button 的 `has-[>svg]` 内边距微调 | 不支持时仅丢弃该规则，属优雅降级 |

另有 `@supports not ((backdrop-filter: blur(1px)))` 分支，为不支持毛玻璃的浏览器提供不透明降级底色，避免文字对比度不足。

**不要**在新增样式里使用 `color-mix()`、`:has()`、范围语法媒体查询或嵌套语法。

## 无障碍对比度：一处刻意偏离参考站的地方

子比的调色板在视觉上很成熟，但**次级灰阶与强调色的对比度达不到 WCAG AA**。本次改造忠实复刻了它的取值，代价是把这个工程的对比度问题放大了：

| 阶段 | 不达标处数 | 说明 |
| --- | --- | --- |
| 改造前（`b5abc85`） | 37 | 原设计用的 `oklch(0.48 0.025 275)` 约 4.8:1，达标 |
| 改造后（`3ad5110`） | 224 | **6.05 倍劣化**，元素总数基本未变（104/115/66/27/25 → 112/115/66/27/25） |
| 灰阶修正后 | 60 | 减少 164 处（73%），剩余全部为强调色 |

不达标项的构成（改造后 224 处）：

| 类别 | 处数 | 占比 | 处理 |
| --- | --- | --- | --- |
| 灰阶文字（`--muted*`） | 160 | 71% | **已修正** |
| 品牌粉 `#ff3f9f` 作文字 | 44 | 20% | 保留 |
| 标签色（蓝 `#2997f7` / 红 `#fe3459`）作文字 | 13 | 6% | 保留 |
| 白字配粉底 / 渐变底 | 7 | 3% | 保留 |

**修正范围经确认后限定为灰阶**：品牌粉是子比的识别核心，动它就等于放弃这次改造的目的；标签色属内容语义色，压暗后与灰阶难以区分。这 60 处是**知情取舍**，不是遗漏。

强调色的实测对比度（均低于 4.5:1，属已知项）：

| 组合 | 对比度 |
| --- | --- |
| `#ff3f9f` 作文字 on `#ffffff` | 3.25:1 |
| `#ff3f9f` 作文字 on `#f5f6f7` | 3.00:1 |
| `#2997f7` 作文字 on `#ffffff` | 3.06:1 |
| `#fe3459` 作文字 on `#ffffff` | 3.59:1 |
| 白字 on `#ff3f9f` | 3.25:1 |

若要进一步达标，最小改动量约为：品牌粉作文字 → `#cf3381`（4.65:1）、作底色 → `#d13382`（4.66:1）、标签蓝 → `#1e70b8`（4.67:1）、标签红 → `#cb2947`（4.65:1）。代价是粉色会明显发暗，识别度下降。

### 取证方式与五个必须注意的坑

脚本：`probe-interaction.mjs`（skill `web-visual-parity/scripts/`）。它同时覆盖 Tab 可达性、聚焦可见性、悬停反馈与对比度。

| 坑 | 后果 | 正确做法 |
| --- | --- | --- |
| `oklch()` 的计算值仍是 `oklch(...)` | 用 `/rgba?\(/` 正则解析会匹配不到，元素被判「无颜色」丢弃。改造前只统计到 6 个元素（实际 100 个）——**据此会得出「改造未影响对比度」的完全相反结论** | 用画布取色：画到 1×1 像素再 `getImageData` |
| 聚焦指示器常画在父级 | `.input-wrap input` 是 `border:0; outline:0`，光环在 `.input-wrap:focus-within` 上，只看元素自身会误报「聚焦不可见」 | 沿祖先链 4 级比对样式 |
| 悬停反馈可能是 `filter` 而非颜色 | `.tag-pill:hover` 只改 `filter: brightness(.96)`，漏测会误报「悬停无反馈」 | 读取属性要包含 `filter` |
| 固定等待会读到过渡中间值 | `sleep 420ms` 读到 `rgb(159,103,131)`——正是 `#777 → #ff3f9f` 的中间态 | 轮询至连续两次读数一致 |
| 白字压在渐变/图片遮罩上 | 只回溯 `backgroundColor` 会把 `.login-quote` 判成「白字配白底 1:1」 | 祖先链检测渐变/图片，命中则标记「无法判定」而非「不达标」 |

## 页面清单（均已视觉核对）

首页、文章列表、文章详情、标签分类、关于、登录、创作台、404、OAuth 回调。

OAuth 回调页有加载与失败两种状态，两者都已实测（该页此前从未被真正渲染过）：

| 状态 | 触发条件 | 实测结果 |
| --- | --- | --- |
| 加载中 | `?auth=success`，会话刷新尚未返回 | 转圈 40px 且完全居中；上边框 `#ff3f9f`（主题色）、其余边框 `rgba(50,50,50,.1)`；`spin .8s linear infinite`；下方状态文案 `#636363` |
| 失败 | `?auth=error&message=...` | 文案 `#fe3459`、15px、水平居中偏差 1px；「返回登录页」按钮 104×38；页面高等于视口高 |

该页会隐藏页头与页脚（见 `App.tsx` 的 `isCallback`），因此这里的 `min-height: 100vh` 不会产生纵向溢出。

> 加载态的取证要注意：成功态会在一次会话刷新后就 `navigate` 走，直接截图只能拍到过渡帧。需拦截 `/api/auth/session` 把请求拖住，页面才会真的停在加载态。脚本：`.scratch/probe-callback.mjs`。

### 一个既有取舍：视口高区块 + 页脚必然溢出

`.route-loading`、`/login`、`/404` 都用视口比例高度，而页脚仍排在其后，于是产生纵向滚动：

| 页面 | 桌面 1280×800 | 移动 390×844 |
| --- | --- | --- |
| `/login` | 193px | 492px |
| `/no-such-page`（404） | 17px | 68px |
| `/studio` 路由加载态 | 193px | — |

这是**既有行为**，不是本次视觉改造引入的。要真正消除，需把 `.site-shell` 改为 flex 纵向布局并让内容区 `flex: 1`——会牵动全部 9 个页面，而收益只是消除一个瞬时状态下的滚动条，风险与收益不成比例，故保留现状并记录在此。

测量脚本：`probe-overflow.mjs`（已沉淀到 skill `web-visual-parity/scripts/`）。

## 如何复验

```bash
node <skill>/scripts/probe-reference.mjs https://www.zibll.com/1997.html   # 重新抓取参考值
node <skill>/scripts/audit-responsive.mjs http://127.0.0.1:5173            # 响应式溢出审计
node <skill>/scripts/audit-compat.mjs dist/assets/*.css                    # 产物兼容性审计
node <skill>/scripts/probe-overflow.mjs http://127.0.0.1:5173              # 纵向溢出基线
node <skill>/scripts/probe-interaction.mjs http://127.0.0.1:5173          # 交互三态 + WCAG 对比度
node <skill>/scripts/shots.mjs                                             # 逐页截图
```

`probe-interaction.mjs` 支持两个环境变量：`ONLY=contrast` 只跑对比度，`DEBUG_CONTRAST=1` 打印元素过滤分布（排查「统计数异常少」时用）。

审计脚本必须对**构建产物**运行，不能只对源码——源码干净不代表产物干净。改动 CSS 后记得重新 `pnpm build`，并确认生产服务真的加载了新产物：产物文件名带内容哈希，哈希变了而服务仍返回旧的资源清单时，页面会请求到 HTML 兜底页而非 CSS，表现为整站无样式。
